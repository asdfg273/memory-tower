# 仪器故障记录（INSTRUMENT_FAILURES）

> 规则：**oracle 必须先在人为污染上失败一次**，否则"全对"只是碰巧。
> 每条记录都写：症状 / 为什么会产生假结论 / 修法 / 自检 / 影响过的数字。
> 这些 bug 不改历史结论的表述就不能引用 —— 所以下面同时写"修订后该怎么说"。

## F1｜拒答被 `ents` 里的单字命中，算成"答对"

- **症状**：`记住我不吃香菜` 的实体表 `ents=["不","香菜"]`；删库后模型答"不知道您是否过敏。"
  因为里面有"不"字，被 `has_key` 判成命中 → `recall_after_delete` 虚高。
- **假结论**：会得出"删库后仍有 15–20% 的记忆泄漏"——听起来像缓存/幽灵记忆，实际是匹配器把拒答读成了答案。
- **修法**：`has_key` 增加拒答兜底——回复命中 `不知道|不清楚|没有(提到|记录)|不在(您|你)的?资料|无法(回答|提供)|没告诉`
  时，匹配池收缩为 `[key]`（不再用 `ents` 里的单字）。
- **自检**：`tools_mem_remember_test.py --self-test-oracle` 第 2 关（"拒答不命中"）。
- **影响**：`recall_after_delete 0.15`（llm）/`0.10`（rules）→ 见 F3 的结构化修订。

## F2｜跨用例变量泄漏：上一例的值被下一例继承

- **症状**：`reply_del` / `recall_del` 在 `try/finally` 里赋值；某用例在删库阶段抛异常时，
  函数末尾用 `locals().get("reply_del")` 取到的是**上一个用例**的值。
- **假结论**：个别用例的"删库后答对"是别人的答案；汇总后随机偏高或偏低。
- **修法**：每个用例开头显式重置 `reply_del=""`、`recall_del=None`、`text_hit_del=None`、
  `retrieved_del=None`，并且返回时直接引用这些局部变量，不再用 `locals()`。
- **自检**：把某用例的删库阶段强制抛异常（人为污染），确认该行 `recall_after_delete` 为 `None` 而不是继承值。
- **影响**：删库对照每行的可信度；对汇总影响 0–1 条。

## F3｜文本匹配无法区分"回忆"与"回声"（本轮最关键）

- **症状**：库已清空、检索列表为空，模型仍可能说出关键词：
  `记住我不吃香菜` → "不，我不太喜欢香菜的味道。"；`记住我喜欢喝美式咖啡` → "…比如美式、卡布奇诺…"。
  纯文本匹配判"命中"，但物理上没有可用记忆。
- **假结论**：把"模型会顺着问句造句"当成"记忆泄漏"。
- **修法（结构化判据）**：删库后那一问同时记录 `retrieved_after_delete`（检索条数）。
  `recall_after_delete = 文本命中 AND 检索条数 > 0`；纯文本命中另记 `text_hit_floor`。
- **自检**：oracle 第 3 关——故意断言"文本会误判为 True"，同时断言"结构化判据为 False"。
- **修订后该怎么说**：
  - `recall_after_delete` = **0.000**（结构口径，检索为空时不可能回忆；2026-10-22 复跑：两臂都是 0.000，
    `n_retrieved_after_delete_positive = 0`）；
  - `text_hit_floor` = **0.100（llm）/ 0.150（rules）**，是旧口径的残余，**匹配器的伪命中地板**，不是记忆效果；
  - 独立探针（`tools_mem_attr_probe.py`，每条独立库、删空后核对 `alive=0`）同样给出 **真回忆 0/4**。
  - 因此"新会话答对来自记忆库"的论证**更强**了：删掉记忆后是 0，不是 15%。

## F4｜问卷式模板泄题（形态实验 C 臂第一版 1.000）

- **症状**：生成"问答对"时把**评测用的问法本身**写进了记忆内容，检索自然 1.000。
- **假结论**："问答对存法最优"。
- **修法**：生成时禁用评测问句（只允许从事实改写，不允许复用评测串）；C 臂降到 0.250。
- **自检**：任何"某臂显著高于其他臂"的结果，先检查该臂内容是否包含评测串（字符串级 grep）。

## F5｜tie 造成的假排名

- **症状**：对未加权的 2-gram 打分，8 个改写问法里有 5 个与全部 362 条记忆的得分都是 **0.0000**
  （`ties=362`）。此时 `rank` 只是数组顺序，rank=3 或 rank=7 没有意义。
- **假结论**：把"rank=3"当成"差一点就对了"，进而以为"加个 IDF 就能救"。
- **修法**：打分同时输出 `ties`（与本条最高分相同的文档数）；`ties == len(corpus)` 的行标注为"无信号"，
  不参与 rank 解释。
- **自检**：`tools_mem_bm25.py` 的 `ties` 列。

### F5b｜ties 升级为一等公民指标（与"recall@k 必须同报常数基线"孪生的规约）

- **症状**：`原始 2-gram 0.375 / IDF 0.375 / BM25 0.375`，逐条完全相同。
  只看 top-1 会把这句话读成"三种打分等效"，实际是"三种打分在同一片零重合的沙漠上并列"。
- **规约（今后所有 top-1 都要遵守）**：
  1. 报 top-1 时必须同报 `ties`：`ties=1` 才是"真的排第一"；`ties=len(corpus)` 是"无信号"。
  2. 报 top-1 时同时报**最高分本身**（0.0000 和 0.35 的 top-1 含义完全不同）。
  3. 当 `ties` 很大时，任何"改打分函数"的结论都必须先证明它把 `ties` 降下来了，否则不算改进。
- **落地**：`tools_mem_qcov.py::ties_of(scores)` 是共享实现；`tools_mem_bm25.py` 的 `ties` 列、
  `tools_mem_form_strict.py` 的记录字段都按此口径输出。
- **反面教材**：本次 IDF 实验里 H1 被推翻，靠的就是 `ties=362` 这个读数——它比 top-1 本身更有信息量。

## 引用纪律（本轮之后）

1. 任何 `recall*` 数字必须注明口径：`ctx`（同会话）/ `new`（新会话）/ `del_struct`（结构口径）/ `text_hit_floor`（匹配器伪命中）。
2. 只引用 `del_struct`，不引用裸的"删库后 0.15"。
3. 报告里出现"某臂明显更高"时，先过一遍 F4 的泄题检查。
4. 任何新 oracle 必须先跑 `--self-test-oracle`，并把"人为污染那一关"的断言写进脚本。
