# 相册一致性：把 Titans 接进 SD1.5 的预注册实验（A 阶段）

状态：2026-11-04 开工。本文件在跑数字之前写死判据，事后不改。

## 问题

同一角色、不同场景的**多张图**（相册）里，身份不稳定。现有解释是"每次采样独立、文本编码装不下脸"。
本项目已证伪过两件事：塔当检索器不成立（§5.12）、塔注入残差流不涨推理（§5.8，
机制是"注入 = 无条件输出指令，缺可分维度与逐事实监督"）。所以本阶段不重复"注入"，而是问：

> **在同等 token 预算与延迟下，定长的测试时状态（塔）能否比"把参考 token 直接塞进注意力"
> 更省、更稳地保持同一角色的身份？**

## 三条预注册假设

- **H1（容量/条件）**：SD1.5 在 256×256、20 步下，参考图条件（不做任何训练）能把 CLIP-I
  身份相似度从"无条件"的基线抬起 ≥ 0.05。若不成立，说明条件通路本身就要训练，先修通路。
- **H2（塔 vs 裸 token）**：同预算（64 token）下，塔读出的残差更新 ≥ 裸 token 拼接的 CLIP-I，
  且延迟更低（注意力长度 64 vs 128）。**这是本阶段的主判据。**
- **H3（写回有用）**：第 k 张图生成后把其中层特征写回塔，第 k+1 张图的 CLIP-I 比"不写回"高
  ≥ 0.03，且多样性（两两 LPIPS）不降。

三条全否 = 这条技术路线在"免训练"设定下走不通，需要转 A′（训练连接器）。

## 臂

| arm | 条件做法 | 预期 | 说明 |
| --- | --- | --- | --- |
| `none` | 纯文本 | 最低 | 锚点，必须先把身份相似度量到"不认识的同一角色"是什么水平 |
| `img2img` | 参考图直接当初始噪声（strength 0.6） | 最高但会抄 | **泄漏上界**，用来验证指标会不会被"复制"骗到 |
| `raw` | 64 个参考 token 拼进 mid-block 自注意力 | 中 | 免训练的条件通路 |
| `tower` | 64 个参考 token 闭式写入塔，读出加在图像 token 上 | 中 | 主判据：同预算更省 |
| `writeback` | `tower` + 每张生成图的中层特征写回 | 不确定 | 用户提的"信息流返回中部再写入" |

## 指标（三条一起报，缺一条就不算数）

1. **身份**：CLIP 图像余弦（参考图 vs 生成图），本地 `openai/clip-vit-base-patch32`。
2. **多样性**：同 prompt 不同种子的两两 LPIPS（或像素 L1，若 LPIPS 不可用）。
3. **指令遵循**：CLIP 文本-图像相似度（场景/姿态词），用来抓"身份高了但图糊成一张脸"。

指标自检（跑数字之前先做）：
- 复制基线（`img2img` strength=1.0，等于原图）身份分应 ≈1.0 → 指标能识别"复制"；
- 无关参考图（另一个人）身份分应显著低于同角色 → 指标能识别"不认识"。

## 规模与成本

- 256×256、DDIM 20 步、单角色、N=6 张（6 个场景 prompt × 1 种子）。
- 8 GB 单卡，fp16，`enable_attention_slicing`；单轮目标 < 3 min。
- 判死条件：若 `tower` 在 CLIP-I 上低于 `raw` 超过 0.02，或延迟优势 < 10%，记负结果收工。

## 不做（本阶段）

- 任何训练（连接器、LoRA、塔的写出权重）；
- 视频/时序（那是另一条线，需要 motion module）；
- SDXL / 中文字体 / 人体解剖质量评估。

## 结果（2026-11-04 回填；机器产物 `reports/repro/album_tower.json`）

**分辨率必须先修**：256×256 在本机（RTX 5060 Laptop / torch 2.11 cu128）生成的是条带状噪声
——SD1.5 的原生分辨率是 512，低分辨率下 UNet 输出不可用。所以下面所有数字都在 **512×512** 上，
mid-block 在该分辨率下是 **64 个 token**（与设计假设一致）。n=6 场景、DDIM 20 步。

| arm | CLIP-I 身份 | CLIP-T 指令 | 多样性 L1 | 秒/张 |
| --- | --- | --- | --- | --- |
| `none` | 0.6879 | 0.3441 | 68.7 | 9.56 |
| `copy`（str 0.15） | **0.9867** | 0.2735 | 5.0 | 1.99 |
| `img2img`（str 0.6） | 0.8986 | 0.2864 | 15.1 | 5.94 |
| `raw`（64 tok） | 0.6902 | 0.3427 | 68.5 | 9.58 |
| `tower`（64 tok） | 0.6901 | 0.3395 | 67.5 | 9.35 |
| `writeback` | 0.6850 | 0.3421 | 66.9 | 9.79 |

指标自检：同一张图 1.0000、**不同角色 0.5210** —— 有效量程 0.52→1.00，
而臂间差异只有 0.002–0.005，**远在噪声带之下**（同臂逐图极差 0.56–0.83）。

### 判据（三条全否）

- **H1 不成立**：`raw` +0.0023、`tower` +0.0022，比 0.05 门槛低一个数量级。
  参考 token 确实改变了像素（逐图分数与 `none` 有差），但**没有改变身份**。
- **H2 不成立**：`tower` 0.6901 对 `raw` 0.6902，差 −0.0001；每张只快 0.23 s（2.4%），
  远不到预注册要求的 10%。同预算下塔与裸拼接**等价**，而不是更优。
- **H3 不成立**：`writeback` 低 0.0051，多样性同时降 0.6。

### 判读

1. **免训练的条件注入在这条通路上无效**：与塔在文本推理上的结论（§5.8、§5.14）同构——
   缺的不是"更省的表征"，而是**让模型消费这段状态的监督**。塔的读出在本例里再准也没用，
   因为 UNet 没有学过"把这段残差当成某个人的身份"。
2. 唯一真正抬身份的是 **img2img 初始噪声**（0.8986），代价是多样性塌到 15（对照 `none` 68.7）
   与指令遵循下降——它是在"抄图"，不是"记住角色"。
3. `none` 自己就有 0.6879，因为身份线索（黑短发、蓝外套）本来就在 prompt 里；
   **真正的对照组是"换措辞"**：同一角色换 6 种描述时身份会不会掉，本阶段没测。

### 下一步（未做，需先定预算）

- **A′ 训练连接器**：参考图 → 少量参数的 cross-attn context token，用少量同角色多场景图训练，
  再在同一套 6 张相册上比 `img2img` 的 0.8986 与 `none` 的 0.6879。本阶段结果正是它的动机。
- 若坚持免训练，改走"参考图作为初始噪声 + 指令解耦"（例如 img2img + 强度日程），而不是改注入位置。

## A′ 训练小投影头（连接器）：训了，**塌了**

脚本 `tools_album_head.py`（build/train/eval 三阶段）。头结构：64 个 mid-block token (1280 维)
→ `Linear(1280→768)+GELU` → 均值池化 → `Linear(768→4·768)` → 4 个 context token 拼在 77 个文本 token 之后，
共 3.3 M 参数，UNet/VAE/文本编码器全部冻结。训练 400 步（AdamW 1e-3、clip 1.0、eps 预测损失）。

数据：2 个训练身份（A 黑短发蓝外套 / B 白胡子红大衣）× 6 场景 = 12 对；目标图由 `img2img(ref, scene, 0.80)`
生成（0.60 时场景几乎不变，等于只教"抄图"）。**留出身份 C**（红发绿裙）完全不参与训练。

| 身份 | 来源 | CLIP-I | 多样性（像素 L1） |
| --- | --- | --- | --- |
| A | 训练集内 | 0.5713 | 60.6 |
| C | **留出，没见过** | 0.5537 | 60.5 |
| 参考基线 `none`（纯文本） | — | **0.6879** | 68.7 |
| 参考基线 `img2img(0.6)` | — | 0.8986 | 15.1 |

- **H4 不成立**：留出 0.5537 远低于门槛 0.80，甚至低于"什么都不加"的 0.6879。
- **机制不是过拟合，是崩塌**：对 A/B/C 三个参考图取训练好的头输出，
  `cos(A,B)=1.0000`、`cos(A,C)=0.9998` —— 头**几乎完全忽略输入**，输出一个常数偏置。
  所以 A 行与 C 行的生成图肉眼几乎一样（`_ab_tmp/album_head_eval/eval_grid.png`）。
- 训练损失 400 步里一直贴在同一水平（0.10–0.12），没有"先降后升"的过拟合曲线，
  说明这个头在当前监督下没有可学的梯度方向：12 个样本、4 个 token 对 eps 损失的影响太小，
  最小化损失最省力的解就是把 4 个 token 调成常数。
- 附带证据：`--stage build` 用 0.60 强度时六张目标图全是同一站姿，**监督信号本身只在教"抄图"**；
  改成 0.80 后场景才真正变化，但两版都指向同一个结论。

### 判读

连接器失败的原因不是容量（3.3 M 对 860 M UNet 足够），也不是训练不足（损失平稳说明无可学信号），
而是**监督形式与数据规模**：要让 4 个 token 承载"这是谁"，需要同一个人在几十到上百张跨场景照片
（IP-Adapter 那一档的量级），12 张合成图只够学一个偏置。这与 §5.14 同向：
**在冻结的主模型里，"值"本身不是瓶颈，把值翻译成主模型能用的话的"接口 + 数据"才是。**

复现：`venv\Scripts\python.exe tools_album_head.py --stage all --steps 400`；
机器产物 `reports/repro/album_head.json`。

## A″ 换成真实人脸数据（CelebA）：塌陷消失，但增益只有 +0.04

数据来源：HuggingFace 镜像上的 `flwrlabs/celeba`（`img_align+identity+attr`），用 `datasets` 流式读了 700 行，
按 `celeb_id` 分组后取 **6 个身份 × 8 张真实照片**（4 个训练身份、2 个留出身份），
身份互不重叠且经 CLIP 余弦核对（同身份 0.86–0.93，跨身份 ≤0.60）。

头换成两层、8 个 context token（≈9 M 参数），监督目标改为"同一人的另一张真实照片"经 img2img(0.75) 的图，
训练 1200 步。评估：每个身份生成 4 个场景，CLIP-I 相对该身份另外 3 张**真实照片**的均值；
`none` 是同样场景、纯文本、无任何身份信号。

| 身份 | 划分 | head | none | Δ |
| --- | --- | --- | --- | --- |
| train_0 | 训练 | 0.4987 | 0.4369 | +0.062 |
| train_1 | 训练 | 0.4853 | 0.4445 | +0.041 |
| train_2 | 训练 | 0.4280 | 0.4241 | +0.004 |
| train_3 | 训练 | 0.4464 | 0.4044 | +0.042 |
| heldout_4 | **留出** | 0.5179 | 0.4884 | +0.030 |
| heldout_5 | **留出** | 0.5679 | 0.5090 | +0.059 |
| 均值 | — | **0.4906** | 0.4512 | **+0.039** |

- **H5 不成立**（留出要求 ≥ +0.10，实测 +0.045）；**H6 也不成立**（训练集要求 ≥ +0.15，实测 +0.037 均值）。
- 但**性质变了**：A′ 里头的输出对三张参考图余弦 0.9998–1.0000（完全塌陷）；A″ 里降到 0.9875–0.9992，
  仍有强常数量+一点身份调制。生成图上能看到偶发"像那个人"（`_ab_tmp/real_eval_grid.png` 上排第 3 张），
  但同一行里也有完全不像的帧。
- 多样性 72.9 → 57.2–61.8，仍在门槛（40）之上，说明不是靠塌多样性换来的。

### 判读

换成真人数据确实**解开了塌陷**，但只走到 +0.04：要把 2048 维图像 token 压成几枚上下文 token
并让冻结的 UNet 认账，需要的不是"几十张照片"，而是**十万对级别的图文对**——
这正是 IP-Adapter 的训练规模（它只训一个 cross-attn 适配器，数据是 LAION 里的同人图像对）。
换句话说：这条路的瓶颈是数据规模，不是结构想法。

### 对产品路线的含义

要解决"相册里同一个人"，在 3–5 张参考图、单机 8 GB 的约束下，能做到的开源方案只剩两条：

1. **直接用预训练的 IP-Adapter**（`h94/IP-Adapter`，SD1.5 版 1.5 GB）：零训练，一张参考图即可，
   身份强度可调；代价是额外 ~1.5 GB 显存与一段 cross-attn 适配器。
2. **每个角色训一个 LoRA / textual inversion**（3–5 张图、10–20 分钟）：身份最强，
   但每个新角色都要单独训练，且要存一份权重。

自研连接器要追到同样效果，需要把数据从 48 张提到至少 10⁴ 量级——在单机环境里不现实。

复现：`venv\Scripts\python.exe tools_album_head_real.py --stage all --steps 1200`（需 `HF_ENDPOINT=https://hf-mirror.com`）；
机器产物 `reports/repro/album_head_real.json`。
