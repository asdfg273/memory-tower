# 记忆检索对照：平台 SQLite vs 记忆塔（C 阶段 + A′ 消融 + 自描述化）

数据：`data/memory.db` 里 28 条真实记忆（全部 `scope=task`、`confidence=0.9`、同一时间戳），
query 38 条（keep 20 条保留原词 / para 18 条零词面重叠改写），k=5，
指标 = 可接受答案集合的首条命中。产物：`_ab_tmp/memory_ab_platform.{json,md}`。

## 结论

1. **平台当前的排序基本就是 bigram 排序**：top-1 与纯词面排序一致 34/38（其余 4 条是并列分的
   tie-break 差异）。因为 28 条记忆的 scope/confidence/updated_at 全相同，平台分
   `0.55*bigram + 0.20*scope + 0.15*confidence + 0.10*recency` 的后三项是常数。
2. **塔不能替代这个词面召回**：keep 组不占优（0.800 vs 0.850），para 组原始状态下持平（0.111）。
   自描述化之后塔（gated）在 para 组反而略高（0.389 vs 0.333），但那是"条目变长→词面也变好"
   带来的，不是语义能力；纯塔读出仍是 0.111。
3. **A′（给记忆追加 LLM 生成问句当塔键）不成立**：4 条问句/条时全线变差，1 条问句/条时
   只有 para 组 +1 条命中、keep 组反降。
4. **唯一确定有效的是自描述化**（把电报式短句改写成完整句子）：平台 pooled 0.500→0.605，
   tower:gated 0.474→0.632，para 组平台 0.111→0.333，弱词面子集 tower:gated 0.136→0.316
   （首次反超平台的 0.263）。

## 自描述化（下一步 1）：真库迁移后复跑（2026-10-26）

用 `tools_memory_selfdesc.py --apply` 逐条走 `MemoryService.update()`（bump version、
写 `memory_versions`、metadata.history 留痕），迁移前自动备份到 `data/memory.db.bak-<ts>`；
版本行 30→58。原始文本快照留 `data/memory_orig.json`（ground truth 定位用）。

改写例：`不要报单点,报覆盖–精度对` → `写报告不要只报单个点的数字，要同时报覆盖率和精度这一对数。`

## 下一步 2 的实测：embedding 通道 —— 负结果

先说结论：**本地 nomic 嵌入在中文短问句上比朴素词面还差，不上线。**

做法：28 条记忆 + 38 条 query，加 `emb`（纯余弦）与 `hyb`（0.5 余弦 + 0.5 bigram）两路召回，
嵌入用 LM Studio 的 `text-embedding-nomic-embed-text-v1.5`（768 维，向量已归一化）。

| 系统 | pooled hit@1 | keep | para | 弱词面 n=19 |
| --- | --- | --- | --- | --- |
| platform（自描述化后） | .605 | .850 | .333 | .263 |
| tower:gated | .632 | .850 | .389 | .316 |
| emb | .263 | .400 | .111 | .053 |
| hyb | .500 | .600 | .389 | .158 |

诊断：`cos(query, 正确条目)` 均值 0.795，`cos(query, 其他条目)` 0.617——分离度只有 0.18，
排序基本靠噪声。这是**模型问题不是融合问题**：nomic 是英文向模型，中文短句挤在同一个锥形区。

- 换融合权重不管用：w_emb = 0/0.1/0.2/0.3/0.5/1.0 →
  pooled .605/.605/.579/.579/.500/.263，para .333/.389/.444/.444/.389/.111。
  只有 w=0.1 略抬 para（+.056）而 keep 掉 -.05，不划算。
- 加 nomic 的任务前缀（`search_query:` / `search_document:`）无效：para 仍 .333。
- RRF（k=60）融合也无效：para .474/.500，低于平台 .556。

emb 分支保留在 bench 里（`--emb-url`），产品链路不接。要重开这条路必须先换中文 embedding 模型。

## 打分器替换：idf 加权 1+2 元（已落地）

embedding 失败后回头查词面打分器本身：`text_score` 对 2-gram 一视同仁，"报告""测试"这类
高频词和"覆盖–精度"这类判别词权重相同，于是**长条目靠通用词就能挤进前排**。

离线扫参（28 条记忆、38 条 query，临时脚本已删）：

| 打分器 | pooled hit@1 | keep | para |
| --- | --- | --- | --- |
| 朴素 2-gram（原） | .605 | .850 | .333 |
| idf 2-gram | .605 | .767 | .389 |
| **idf 1+2 混合（w_uni=0.5）** | **.684** | .800 | **.556** |
| idf 3-gram | .395 | .421 | .333 |

w_uni=0.3/0.4/0.5 结果完全一致（.684/.868），0.6 退到 .658，1.0（纯 unigram）退到 .632；
逐条看是 5 胜 2 负。

改动（`memory_service.py`）：

- 新增 `_char_grams()` / `_term_freq()` / `_cosine_idf()` / `text_score_idf(query, text, idf1, idf2, w_unigram=0.5)`
- `MemoryService._idf_tables()`：以 `(COUNT(*), MAX(updated_at))` 为缓存键，`idf = log((n+1)/(c+0.5))`
- `get_relevant()` 内部改用它

产品路径复跑（真库、`MemoryService.get_relevant`）：

| 指标 | 改前 | 改后 |
| --- | --- | --- |
| pooled hit@1 | .605 | **.658** |
| pooled hit@3 | .711 | **.868** |
| keep hit@1 | .850 | .750 |
| keep hit@3 | .950 | .950 |
| para hit@1 | .333 | **.556** |
| 弱词面 hit@1 | .263 | **.421** |

keep 组掉 2 条 top-1，但 hit@3 仍是 .950——信息还在前三条里，只是排序变了。
pooled 净 +.053 hit@1 / +.157 hit@3，para +.222，这个交换值得。

**没改的两处（要决策）**：`MemoryService.find_by_text`（min_score 阈值语义敏感）与
`chat_app.py:1450-1454` 的二段重排仍用旧 `text_score`——产品里两套打分并存，长期会漂移。

## 机制

- 塔的读出是闭式解 `W=(KᵀK+λI)⁻¹KᵀZ`，键数 28→137 时同一条事实的能量被摊到 5 个键上，
  纯塔 pooled hit@1 从 0.342 掉到 0.289；para 组 0.111 → 0.056。
- `fusion=gated` 只要有任何词面命中就整条按词面排，而 7B 生成的问句常跑题
  （给"不要报单点，报覆盖–精度对"生成的是"开发规范有哪些硬性要求"），
  于是噪声键把错误记忆顶到 top-1：para 组 tq:gated 直接 0.000。
- 塔在零重叠改写上从未超过 0.278（hit@3），它做的是"实体键读出"，不是语义检索。
- 词面弱到无法排序时（弱词面子集），gated 才真正轮到塔读出，这时它比平台高 0.053；
  但 n=19，置信区间很宽，只能算"有边际价值"。
